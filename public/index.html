Whether injected CO2 stays underground, whether a fuel cell floods, whether a chip package traps a void: each is decided in pores a few micrometres wide, where an interface pins at a throat and then suddenly floods the next pore. PoreML gives machine learning the data and the yardstick to learn these dynamics in 3D.

Three parts, one pipeline

From geometry to scored prediction, every stage is open and reproducible.

  1. Simulate

    bob is a GPU-native, JAX-based colour-gradient lattice Boltzmann solver (D3Q19, MRT collision) with geometric wetting control. It shards across GPUs for large domains and is checked against eight analytical and experimental benchmarks.

  2. Store

    PoreML data holds every run as a time series of 3D phase, pressure and velocity fields, sweeping contact angle and viscosity ratio over generated media and micro-CT scans of real rock and fuel-cell paper.

  3. Learn and evaluate

    poreml trains surrogates to predict the next frame and scores them over 64-step autoregressive rollouts, with field errors and Minkowski functionals that check volume, interface area, curvature and topology.

What the benchmark shows

Five architectures, three on voxel grids and two on point clouds, trained frame to frame and fine-tuned with the pushforward trick.

One step is easy. Sixty-four is not.

Every model reaches a phase error of 0.002–0.012 on a single step. Over a 64-step rollout the ranking reshuffles: AB-UPT has the lowest phase error in all four scenarios, while P3D keeps the best interface geometry in drainage.

Low error does not mean the right shape.

Topology is the hardest thing to get right. The median Euler-characteristic error is 3.6 miscounts per 105 voxels, as large as the true value itself, and the most accurate model by field error is also best on topology in only one scenario.

Transfer works, with caveats.

Phase errors stay bounded on micro-CT rock and on domains twice as wide, and AB-UPT leads five of six transfer blocks. Volume and interface-area errors grow faster than field error when the domain is scaled up.

Get started

Everything is MIT-licensed. Download a slice of the data, or clone the code.

Download the data

Trajectories use Zstandard compression, so import hdf5plugin before h5py. Filter by scenario, geometry family or run with --include.

pip install huggingface_hub hdf5plugin h5py
hf download PoreML/PoreML_data --repo-type dataset \
  --include "drainage/runs/sphere/*" --local-dir data

Read a trajectory

Each run is one .h5 file holding the solid mask and, per stored step, phase phi, pressure p and velocity u. The last axis is the flow direction.

import glob, hdf5plugin, h5py

path = glob.glob("data/drainage/runs/sphere/*/*/*.h5")[0]
with h5py.File(path) as f:
    rock = f["rock"][:]                    # 1 = solid
    steps = sorted(f["steps"], key=int)
    phi = f["steps"][steps[-1]]["phi"][:]  # NaN inside solids

Run the code

The solver generates new simulations; the framework trains and scores models with the protocols used in the paper.

git clone https://github.com/PoreML/bob      # LBM solver
git clone https://github.com/PoreML/poreml   # learning framework
